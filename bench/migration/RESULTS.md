# Migration benchmark results

Can one coding agent, given only [docs/guide.md](../../docs/guide.md) and a legacy Spring app,
migrate its views to Tessera autonomously with no breakages? How the benchmark works:
[README.md](README.md). Raw per-run output: `results/<app>/run-<k>/`. Table regenerated by
`bench.py report`: [results/summary.md](results/summary.md).

**Setup (2026-10-22).** Tessera 0.1.0-SNAPSHOT at `9757c5d`, the guide at the same commit.
Agent: Claude Code 2.1.308, `claude -p` with model `opus` (claude-opus-5-5), fresh container, no web
access, 90-minute and $40 budget per run (no run hit either). 3 runs per app, 15 runs in total,
about $138.

## Headline

**9 of 15 runs pass outright, and every run of every app builds and passes all of the app's
tests.** The easy apps pass 8/9 (all of Thymeleaf and Mustache petclinic, 2/3 JSP petclinic); the
two hard apps pass 1/6, but their failing runs still render 96–99% of pages identically. No
run used `SafeHtml.unchecked`/`TrustedUrl.unchecked` or weakened security, and none left
legacy templates or the old engine behind.

Every failure traces to a Tessera gap (4 causes) or a guide gap (2 causes). None is a plain
agent error: where an agent got something wrong, it was in a workaround that Tessera or the guide
forced on it.

## Observations

- **Difficulty scales with Spring integration, not template syntax.** All three engines' syntax
  converted cleanly. Agents spent their time on starter/version wiring (#116, #117, #118),
  layouts (#139) and form binding (#120, #123, #126, #127, #133).
- **Agents check their own work.** The reports describe capturing the old pages and comparing
  them with the migrated ones (petclinic run 1, for example, compared 36 responses). The
  failures above are mostly cases the agent's own comparison didn't reach, or differences it
  judged acceptable and documented.
- **Security improvements show up as differences.** JSP and FreeMarker printed some values
  unescaped (validation messages, `${exception.message}`); Tessera escapes them. The normalizer
  compares text content, so these count as identical. fredbet rendered stored rich text with
  `th:utext`; the agents replaced it without `SafeHtml.unchecked` (run 2 with an allow-list
  parser), losing inline styles.
- **Cost.** Easy apps take about 10 minutes and $3; the hard apps about 30 minutes and
  $17–20, using 200k–370k output tokens.

## Harness lessons

The first scoring pass flagged many differences that a browser would never show. The normalizer
(`lib/crawl.py`) now compares what a browser builds. It:
- drops end tags that close nothing, and prints implicit and explicit closes alike;
- treats optional end tags (`li`, `option`, `td`, ...) the same whether written or not;
- keeps the first of duplicate attributes, as browsers do, and drops attribute names left by unbalanced quotes;
- gives boolean attributes and empty `input` values no value;
- ignores whitespace between JSON tokens in scripts and the version segment of webjar URLs;
- masks CSRF tokens, session ids, UUIDs and timestamps.

Baselines were crawled twice to check that they are deterministic. One per-app accepted
difference remains: JobSearch's `ignore` in `app.json`, an attribute built from an unbalanced
quote in the original template. The crawl lists also avoid requests where the original app
itself crashes or picks an error message at random.

These #115 runs were crawled and scored with `lib/crawl.py`. Since #151 the harness records and
compares with `tessera-migrate record`/`compare` instead (see [README.md](README.md)).

## Limitations

- **FreeMarker coverage is weaker than the rest.** No permissively licensed Boot 3 FreeMarker
  app with seed data and real tests could be found. JobSearch has no license (its patches aren't
  committed), a single context-loads test, and an employer role the crawl can't reach because of
  an app bug. 41 of its 49 templates are crawled; the rest need uploads or e-mailed tokens.
- **No Velocity app.** Spring 5+ dropped Velocity support. Mustache stands in for the
  Velocity-like slot.
- **Some templates aren't crawled.** fredbet's crawl covers 45 of 46 templates; system info shows
  the host name. Pages that need HTMX headers or multipart uploads aren't crawled at all.
- **Three runs per app is a small sample.** The hard apps' results vary between runs, so their
  pass rate is uncertain.
- **The two Thymeleaf petclinics come from one family.** spring-petclinic is the app Tessera's
  own port (`examples/petclinic`) was built from. The agents never saw that port, but Tessera
  was shaped by it.

## Re-running

`bench/migration/run.sh` rebuilds the image from this repo's `HEAD`, re-baselines every app, runs
3 migrations per app and writes `results/summary.md`. It costs about $140 and 3 hours with 2
parallel jobs. `bench.py recheck` re-runs build, crawl and tests on existing runs, and `rescore`
re-scores them, after a harness change. The one-command path was checked end to end with
`run.sh --runs 1 --first-run 9 spring-petclinic` (image, baseline, one migration, score: pass,
9.5 minutes, $2.72); that throwaway run is not part of the results above.
