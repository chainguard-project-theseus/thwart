# Migration benchmark results

Can one coding agent, given only what we ship (the guide, and since #174 the Claude Code plugin)
and a legacy Spring app, migrate its views to Tessera on its own without breaking anything? How
the benchmark works: [README.md](README.md). Raw per-run output: `results/<app>/run-<k>/`. Table
regenerated by `bench.py report`: [results/summary.md](results/summary.md).

Agent in every round: Claude Code 2.1.308, `claude -p`, model `opus` (claude-opus-5-5), fresh
container, no web access, 90-minute and $40 budget per run.

## At a glance

| Round | Runs | Apps | Scored with | Passed |
|---|---|---|---|---|
| [#115 baseline](#115-baseline) (runs 1-3) | 15 | 5 development apps | `lib/crawl.py` | **9/15** |
| [#151 batch](#151-batch-runs-4-5) (runs 4-5) | 12 | 8 development runs, 4 held-out runs | `tessera-migrate compare` | dev **2/8**, held-out **1/4** |
| [Version-ladder quick round](#version-ladder-quick-round-run-7) (run 7) | 6 | 5 petclinic rungs + jpetstore | `tessera-migrate compare` | **5/6** |

Across all 33 runs, every migrated app builds and passes all of its tests, and no run used
`SafeHtml.unchecked`/`TrustedUrl.unchecked`, `permitAll`, CSRF disabling or `@Disabled`. Only
one run (budgetmaster run 4, which stopped early) left legacy templates behind.

The #151 scoring is stricter than #115's: `tessera-migrate compare` doesn't repair broken markup
or normalize script whitespace the way `crawl.py` did, and it compares dates. Of the 7 failing
runs in the #151 batch's development set and run 7, 3 fail only on differences triaged as
acceptable (below). Counting those as passes gives development apps 8/12 and held-out apps 1/4.

The triage also checked every gap the agents listed in their reports and filed the verified ones,
even those that caused no page difference: 22 Tessera issues (#116 to #137) and 10 guide issues
(#138 to #147). #116, #117 and the guide issues are fixed. Observations from this round:

- **Difficulty scales with Spring integration, not template syntax.** All three engines' syntax
  converted cleanly. Agents spent their time on starter/version wiring (#116, #117, #118),
  layouts (#139) and form binding (#120, #123, #126, #127, #133).
- **Agents check their own work.** The failures are mostly cases the agent's own comparison didn't
  reach, or differences it judged acceptable and documented.
- **Cost.** Easy apps take about 10 minutes and $3; the hard apps about 30 minutes and $17-20.

### Issues

Filed from this triage (label `migration-bench`):

- #181 `SafeHtml` from stored rich text: an allow-list sanitizer, and composing `SafeHtml`
  (jprime 4; also fredbet #115 runs 1-3, budgetmaster 5)
- #182 `style`: accept a validated CSS value and literal-only conditionals (budgetmaster 4, 5;
  jprime 4)
- #183 `tessera-migrate compare`: ignore whitespace between JSON tokens in scripts (jobsearch 5;
  budgetmaster)

Existing issues cited, with the new evidence added as a comment: #119, #121, #122, #125, #136.

How often the first #115 issues came up in the 18 runs of the #151 batch and run 7:

| Issue | Page differences | Worked around |
|---|---|---|
| #118 processor in testCompile | 0 | 18/18 runs set `<proc>none</proc>` for test compilation (12 have `@TemplateFunctions`) |
| #119 null link parameter | 1 run (fredbet 5, 2 pages) | jpetstore 4 and 7 rely on the current `?name` output for valueless parameters |
| #120 null `<select>` | 0 | fredbet 4 and 5 (`t:selected` per option) |
| #121 beans in script `[[...]]` | 2 runs (fredbet 4, 5; 1 page each) | budgetmaster 4 and 5 pass JSON strings through `JSON.parse` |
| #122 `ResourceUrlEncodingFilter` | 0 after the bench ignores (budgetmaster 4 before) | 7 runs register the filter themselves |
| #123 indexed form paths | 0 | 6 runs hand-write the binding (jobsearch 4, 5; jpetstore 4, 7; jprime 4; purl-server 4) |

### Guide gaps

Listed here, not fixed in this PR:

- **How values print.** Tessera prints an enum with `toString()`; JSP EL and Spring's form tags
  print `name()` (jprime 4). Grouped numbers (FreeMarker's default) need #125 or a function.
- **Broken legacy markup.** The guide mentions "broken markup the old engine passed through" only
  in passing. Agents met stray quotes, `<span">` and unclosed `<div>`s (mustache 4, jprime 4,
  budgetmaster 5) and had no advice on rebuilding the DOM the browser built, or on what compare
  will report.
- **Script output is JSON.** The guide doesn't warn that `[[...]]` replaces JS literals with JSON
  (single to double quotes, no trailing commas), which compare then reports (budgetmaster 5).
- **Old engines that fail mid-page.** JMustache throws on a missing `{{variable}}` and returns a
  truncated page; the guide's "a missing attribute is null" doesn't cover it (mustache 4).

### Harness follow-ups

Not done here: the date rollover needs the baseline and the check on the same UTC day (or a
pinned clock, as budgetmaster has); jobsearch needs an ignore for its broken `spring.status.error`
attribute, and spring-petclinic-mustache one for `<span">`. With those, jobsearch run 4 would pass.

## Version-ladder quick round (run 7)

Image built after the plugin shipped (#174, #177), so these runs had the `tessera:migrate` skill;
all six listed and invoked it. One run each of the five petclinic rungs (old commits of the two
petclinics, all on JDK 8; see [README.md](README.md#adding-an-app)) and jpetstore.

| App | Stack | Pass | Tests | Pages same + reordered | Minutes | Cost $ |
|---|---|---|---|---|---|---|
| spring-petclinic-boot27 | Boot 2.7, Thymeleaf 3.0 | yes | 42/42 | 29+1/30 | 5.7 | 1.81 |
| spring-petclinic-boot20 | Boot 2.0, Thymeleaf 3.0 | yes | 43/43 | 27+1/28 | 8.9 | 2.05 |
| spring-petclinic-boot15 (below floor at the time) | Boot 1.5 (Spring 4.3), Thymeleaf 2.1 | yes | 43/43 | 28+0/28 | 12.5 | 2.68 |
| spring-framework-petclinic-spring5 | Spring 5.3 MVC, JSP | yes | 66/66 | 27+0/27 | 20.7 | 3.19 |
| spring-framework-petclinic-spring43 (below floor at the time) | Spring 4.3 MVC, JSP, Tomcat 7 | yes | 67/67 | 27+0/27 | 12.1 | 3.57 |
| jpetstore | Boot, Thymeleaf, Java 8 | no | 9/9 | 58+0/59 | 27.4 | 5.58 |

**5 of 6 pass; every ladder rung passes.** Both below-floor rungs passed **without upgrading
Spring**. Each agent noted that Tessera documented Spring 5.0+ / Boot 2.0+, found that the starter
worked on Spring 4.3 (Boot 1.5's auto-configuration, or wired by hand without Boot), and kept the
app's Spring version rather than take on an upgrade. Both pinned `maven-compiler-plugin` 3.8.1 for
`annotationProcessorPaths`.
That evidence led to #178: since #179 Tessera supports Spring 4.3+ / Boot 1.5+, so these two rungs
are no longer below the floor. jpetstore's one differing page is the same acceptable fix as run 4
(the first name is now escaped).

Three rung agents reported that a null link path variable fails the render where Thymeleaf
printed `null` (documented in guide sections 4.5 and 7). The apps' tests render owners without
ids, so the agents had to guard those links.

Run 7's results directories were deleted by a coordinator error after scoring. Their `agent.json`
files were rebuilt from `bench.py`'s log (wall time, cost, skill use; marked `"reconstructed"`),
so **their token counts and transcripts are lost**. `diff.patch` and `MIGRATION-REPORT.md` come from
the surviving checkouts, and the check, compare and score were regenerated with `bench.py recheck`.

## Limitations

- **Small samples.** One or two runs per app in #151 and run 7; the hard apps vary between runs.
- **FreeMarker coverage leans on two apps.** JobSearch has no license (its patches aren't
  committed) and a single context-loads test; BudgetMaster is held out.
- **No Velocity app.** Spring 5+ dropped Velocity. Mustache stands in for the Velocity-like slot.
- **Not every page is reachable.** Pages that need multipart uploads, cookies the tool can't set,
  captchas or HTMX headers aren't recorded.
- **The Thymeleaf petclinics are one family.** spring-petclinic is the app Tessera's own port
  (`examples/petclinic`) was built from. The agents never saw that port, but Tessera was shaped by
  it.
- **Different rounds, different setups.** #115 used the guide and `crawl.py`; runs 4-5 the guide
  and record/compare; run 7 the plugin. Pass rates across rounds aren't directly comparable.

## Re-running

`bench/migration/run.sh` rebuilds the image from this repo's `HEAD`, re-baselines every app, runs
3 migrations per app and writes `results/summary.md`. `bench.py migrate --first-run K <apps>` adds a
quick round. `bench.py recheck` re-runs build, compare and tests on existing runs (from the
checkouts in `work/runs/`), and `rescore` re-scores them, after a harness change. Runs from #115
were scored by `lib/crawl.py`; `rescore` leaves them alone.
