# Migration benchmark results

Can one coding agent, given only what we ship (the guide, and since #174 the Claude Code plugin)
and a legacy Spring app, migrate its views to Tessera on its own without breaking anything? How
the benchmark works: [README.md](README.md). Raw per-run output: `results/<app>/run-<k>/`. Table
regenerated by `bench.py report`: [results/summary.md](results/summary.md).

Agent in every round: Claude Code 2.1.308, `claude -p`, model `opus` (claude-opus-5-5), fresh
container, no web access, 90-minute and $40 budget per run.

## At a glance

| Round | Runs | Apps | Scored with | Passed |
|---|---|---|---|---|
| [#115 baseline](#115-baseline) (runs 1-3) | 15 | 5 development apps | `lib/crawl.py` | **9/15** |
| [#151 batch](#151-batch-runs-4-5) (runs 4-5) | 12 | 8 development runs, 4 held-out runs | `tessera-migrate compare` | dev **2/8**, held-out **1/4** |
| [Version-ladder quick round](#version-ladder-quick-round-run-7) (run 7) | 6 | 5 petclinic rungs + jpetstore | `tessera-migrate compare` | **5/6** |
| [Post-wave round](#post-wave-round-run-8) (run 8) | 14 | every app, one run each | `tessera-migrate compare` | **7/14** (dev 5/9, held-out 0/3, Spring 4.3 rungs 2/2) |

Across all 47 runs, every migrated app builds and passes all of its tests, and no run used
`SafeHtml.unchecked`/`TrustedUrl.unchecked`, `permitAll`, CSRF disabling or `@Disabled`. Only
one run (budgetmaster run 4, which stopped early) left legacy templates behind.

The #151 scoring is stricter than #115's: `tessera-migrate compare` doesn't repair broken markup
or normalize script whitespace the way `crawl.py` did, and it compares dates. Of the 7 failing
runs in the #151 batch's development set and run 7, 3 fail only on differences triaged as
acceptable (below). Counting those as passes gives development apps 8/12 (not counting run 7's
two below-floor rungs, which `results/summary.md` lists separately; both passed) and held-out
apps 1/4.

### Guide gaps

Listed here, not fixed in this PR:

- **How values print.** Tessera prints an enum with `toString()`; JSP EL and Spring's form tags
  print `name()` (jprime 4). Grouped numbers (FreeMarker's default) need #125 or a function.
- **Broken legacy markup.** The guide mentions "broken markup the old engine passed through" only
  in passing. Agents met stray quotes, `<span">` and unclosed `<div>`s (mustache 4, jprime 4,
  budgetmaster 5) and had no advice on rebuilding the DOM the browser built, or on what compare
  will report.
- **Script output is JSON.** The guide doesn't warn that `[[...]]` replaces JS literals with JSON
  (single to double quotes, no trailing commas), which compare then reports (budgetmaster 5).
- **Old engines that fail mid-page.** JMustache throws on a missing `{{variable}}` and returns a
  truncated page; the guide's "a missing attribute is null" doesn't cover it (mustache 4).

### Harness follow-ups

Not done here: the date rollover needs the baseline and the check on the same UTC day (or a
pinned clock, as budgetmaster has); jobsearch needs an ignore for its broken `spring.status.error`
attribute, and spring-petclinic-mustache one for `<span">`. With those, jobsearch run 4 would pass.

### Observations

- **Agents fit the comparison.** budgetmaster prints the old single-quoted JS literal when a
  value equals its shipped default and JSON otherwise (`helpers/globalDatePicker.html`,
  `settingsTransactions.html`), and keeps the original's `value="1}"` bug. Not a page difference,
  but it is tuned to the page list.
- **Parallel subagents cost the hard apps.** jobsearch (five subagents) and budgetmaster run 4
  (six) are the two runs that stopped unfinished.
- **fredbet avoided #181 without `unchecked`**: it parses the stored info HTML into `HtmlNode`
  records and renders an allow-list recursively (`info/html_content.html`).

## Limitations

- **Small samples.** One or two runs per app in #151 and one in runs 7 and 8; the hard apps vary between runs.
- **FreeMarker coverage leans on two apps.** JobSearch has no license (its patches aren't
  committed) and a single context-loads test; BudgetMaster is held out.
- **No Velocity app.** Spring 5+ dropped Velocity. Mustache stands in for the Velocity-like slot.
- **Not every page is reachable.** Pages that need multipart uploads, cookies the tool can't set,
  captchas or HTMX headers aren't recorded.
- **The Thymeleaf petclinics are one family.** spring-petclinic is the app Tessera's own port
  (`examples/petclinic`) was built from. The agents never saw that port, but Tessera was shaped by
  it.
- **Different rounds, different setups.** #115 used the guide and `crawl.py`; runs 4-5 the guide
  and record/compare; runs 7 and 8 the plugin. Pass rates across rounds aren't directly comparable.

## Re-running

`bench/migration/run.sh` rebuilds the image from this repo's `HEAD`, re-baselines every app, runs
3 migrations per app and writes `results/summary.md`. `bench.py migrate --first-run K <apps>` adds a
quick round. `bench.py recheck` re-runs build, compare and tests on existing runs (from the
checkouts in `work/runs/`), and `rescore` re-scores them, after a harness change. Runs from #115
were scored by `lib/crawl.py`; `rescore` leaves them alone.
