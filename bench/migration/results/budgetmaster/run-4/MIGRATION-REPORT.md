## What changed

### Build
- `BudgetMasterServer/pom.xml`: `spring-boot-starter-freemarker` replaced by
  `dev.tessera:tessera-spring-boot-starter:0.1.0-SNAPSHOT` (Boot 3.5 / jakarta). `maven-compiler-plugin`
  runs the Tessera annotation processor next to Lombok and `hibernate-jpamodelgen` (which
  `annotationProcessorPaths` would otherwise switch off), with `-Atessera.templates` and
  `-Atessera.package=de.deadlocker8.budgetmaster.templates.generated`; test compilation runs with
  `<proc>none</proc>` (guide §2, #118).
- `application.properties`: the `spring.freemarker.*` settings are gone.

### Shared view infrastructure (`de.deadlocker8.budgetmaster.view`)
- `PageContext` + `PageContextAdvice`: model attribute `page` with everything the page chrome reads
  (settings, dark theme, the green/red text colour classes that used to be FreeMarker `<#global>`s,
  notifications, the current account and its budget string, update/test/debug flags, backup and
  what's-new reminders, the account end-date reminder).
- Removed FreeMarker-only advices: `StaticClassesAdvice` (exposed `BeansWrapper.getStaticModels()` as
  `static` so templates could call arbitrary static methods), `ServiceAdvice` (exposed four Spring
  services as model attributes so templates could call their methods), `NotificationAdvice` (folded into
  `PageContextAdvice`; both popped the same session attribute).
- Function namespaces: `locale` (the app's own `Localization` bundles, exactly what the templates
  called before), `view` (`initial`, `fontColor`, `c`), `links` (`root()` = `<@s.url ''/>`),
  `entityType` (`of('HOME')` replaces static access to the enum), plus per-area classes.
- `@TemplateView` on every JPA entity and on `Notification`.
- `templates/helpers/colors.html`, generated by `migration/tools/gen_colors.py` — see "Shortfalls".

### Parity tooling
- `migration/pages.txt` (97 requests: login failure/success, every list, every form empty / with
  validation errors / after success, edit pages, delete modals, AJAX modal fragments, error pages 404/405/500)
  and `migration/baseline/` recorded from the original app.

## Shortfalls of Tessera / the guide

1. **Inline `style` with data.** Category, account and template colours are user data printed into
   `style="background-color: …"` / `style="color: …"`. Tessera rejects every expression in `style` and
   offers only `t:class`. Without `SafeHtml.unchecked` there is no way to emit such an attribute.
   Workaround: `helpers/colors.html` switches over the colours the app actually offers (its 17-colour
   palette, the default category colours and the light/dark font colours, both letter cases) with one
   literal `style` per case. A colour outside that list (picked with the custom colour picker) renders
   the element without its `style` attribute. A typed CSS-colour value (like `TrustedUrl` for URLs)
   would remove the need for this.
2. **FreeMarker is not covered by `tessera-migrate`** (Thymeleaf only), so all 75 templates were
   converted by hand.
3. **Attributes from macros.** `validation.ftl` wrote attributes onto the caller's element, and
   fragments can't do that. Each call site now writes four `t:` attributes that call `validation.*`.
4. **A `BindingResult` outside `t:object`** (stored under a custom model key `error`) can't be read. It
   needs an interceptor and a view-safe copy (`ValidationErrors`).
5. **Raw markup and JS.** Localization strings that contain `<br>`/`<a>` (the about credits, the
   first-use steps, news, the 418 page) can't be inserted without `SafeHtml.unchecked`. Splitting on
   `<br>` handles `<br>`; links come out escaped. User chart scripts are JavaScript that used to be
   printed raw into `<script>`; Tessera can only write JSON there, so the planned workaround is
   `eval` of a JSON string.
6. **`data:` image URLs** are turned into `about:invalid`. The image picker now loads images from a new
   `/media/getImageByID/{ID}` endpoint.
7. **No default fragment arguments.** Every call of the button fragments needs 10 arguments, and
   `onclick` was silently lost from `buttonSubmit` in the process.
8. **The processor can't see Lombok getters** (`AccountsFilterConfiguration` needed hand-written ones).
   **A template variable hides a function namespace of the same name**; write `#ns.fn(...)` instead.
   Spring Data `Page` is not view-safe. Enums that override `toString()` need a function to print
   `name()`. Neither of the last two is documented.
9. **Data from the session.** Values that FreeMarker read from the session (`expose-session-attributes`,
   e.g. `filterConfiguration`, `accountsFilterConfiguration`) now silently print nothing. They were found
   only by reading the controllers.
10. **`t:replace` runs before `t:if`/`t:each`** on the same element, so every conditional or looped
    fragment call needs an extra `<t:block>`. This is documented, but it is easy to trip over.
11. **Expected differences that remain:** old broken markup (stray quotes in `classes='"…'`) is now
    well-formed; JSON in scripts is compact or double-quoted; search links are URL-encoded; colours
    outside the known list lose their `style`.

## Security
No `SafeHtml.unchecked`/`TrustedUrl.unchecked`, no new `permitAll` (WebSecurityConfig is unchanged), CSRF untouched (Tessera adds the token
input to POST forms; the explicit `_csrf` inputs were removed), no escaping turned off, no tests
disabled.
