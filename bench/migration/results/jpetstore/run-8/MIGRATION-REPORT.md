# Migration report: Thymeleaf → Tessera

## Result

| Check | Status |
|---|---|
| Every page is rendered by Tessera | Yes. All 19 Thymeleaf templates were rewritten as Tessera templates under `src/main/resources/templates`. The Thymeleaf starter, `thymeleaf-extras-springsecurity4`, `thymeleaf-layout-dialect` and the `SpringTemplateEngine` configuration are gone. |
| Build on the target JDK (8) | `mvn clean verify` with `/usr/lib/jvm/java-1.8-openjdk`: compile and **all tests pass** (6 existing Selenide tests unchanged, plus 3 new rendering tests). The build then fails in `dependency-check-maven:check`, the same way the **unmodified** application does (see "Pre-existing build problems"). |
| Page parity | `tessera-migrate compare` on `pages.txt` (84 requests): **84 same, 0 reordered, 0 differ**, exit 0. |
| Security | No `SafeHtml.unchecked` / `TrustedUrl.unchecked`, no new `permitAll`, CSRF untouched (Tessera adds the `_csrf` input to POST forms, like Thymeleaf did), no tests disabled or changed. Two places that printed database HTML raw now render it safely (see below). |

## What changed

### Build (`pom.xml`)
- Replaced `spring-boot-starter-thymeleaf`, `thymeleaf-extras-springsecurity4` and `thymeleaf-layout-dialect` with `dev.tessera:tessera-spring-boot-starter-javax` (Boot 2.0 is `javax.servlet`).
- `maven-compiler-plugin`: `annotationProcessorPaths` with Lombok (it was found by discovery before; listing paths turns discovery off) and `tessera-compiler`; `-Atessera.templates`, `-Atessera.package=com.kazuki43zoo.jpetstore.templates`, `-Atessera.messages` (message keys checked at build time); `<parameters>true</parameters>`.
- `license-maven-plugin`: excluded the migration artifacts `pages.txt`, `baseline/**` and `.tessera/**`. The plugin runs `format` on every build and was putting a license header into `pages.txt`, which then no longer parsed as a request list.
- `groovy` stays. The MyBatis mappers are Groovy.
- The Spring Boot version (2.0.6) is unchanged.

### Java
- `config/WebMvcConfig`: removed the Thymeleaf `SpringTemplateEngine` customisation. The existing `@ControllerAdvice` now also adds a `layoutView` model attribute (`ui/LayoutView`, `@TemplateView`) with everything the layout used to read from outside the model:
  - `errorResponse`, which replaces `#request.getAttribute('javax.servlet.error.status_code') ge 400`;
  - `searchKeywords`, which replaces the `@productSearchCriteria` bean. It is read lazily at render time, because the search handler sets the keywords after `@ModelAttribute` methods run;
  - `account`, the signed-in user's `Account`, which replaces `#authentication.principal.account` and `sec:authentication`.
- Controllers now put into the model what templates used to read as beans:
  - `CartController`: `cart` and `favourite`, the session-scoped proxies;
  - `AccountController` and `MyAccountController`: `clLanguages` and `clCategories`;
  - `MyOrderController`: `clCreditCardTypes`.
- `config/TesseraTemplateAvailabilityProvider` plus `META-INF/spring.factories`: they tell Boot's `DefaultErrorViewResolver` that `error/404`, `error/400` and `error/500` exist as Tessera templates. Without this, Boot cannot see them and falls back to the Whitelabel page. The Whitelabel page itself is unchanged and still used for statuses that have no template (e.g. 403), as before.
- `component/view/ViewFunctions` (`@TemplateFunctions("view")`):
  - `amount(BigDecimal)` replaces `#numbers.formatDecimal(x, 1, 'COMMA', 2, 'POINT')`, with grouping and HALF_EVEN like Thymeleaf. Tessera's `numbers.formatDecimal` has no grouping.
  - `imageSrc(String)` / `text(String)` split the sample data's `<image src="...">text` descriptions and banners into a URL and a text part.
- `@TemplateView` added to the classes templates read: `Account`, `Category`, `Item`, `Order`, `OrderLine`, `Product`, `Cart`, `CartItem`, `Favourite`, `ProductSearchCriteria`, `AccountForm`, `OrderForm`, `CartUpdateForm(.Line)`, `Messages(.Message)`.
- `CartUpdateForm.Line.getQuantity()` is written by hand instead of generated by Lombok. This works around a Tessera code-generation bug (see below).

### Templates
- `layout.html` is now a `layout(Fragment content, LayoutView layoutView, Messages messages)` fragment. Each page replaces itself with it and passes its `<section>` (`~{::section}`), which reproduces `layout:decorate` / `layout:fragment="content"` exactly.
- `sec:authorize="isAuthenticated()"` became `auth.isAuthenticated()`.
- `th:include="account/flagments :: commonForm"` became `t:insert` of a fragment `commonForm(AccountForm accountForm, List<String> clLanguages, List<String> clCategories)`. The fragment's root has `t:object="accountForm" t:remove="tag"`, so only its children go into the host `<div>`, as `th:include` did.
- `*{lines[__${cartItemStat.index}__].quantity}` became `*{lines[cartItemStat.index].quantity}`.
- `#ids.prev(...)` and Thymeleaf's numbered checkbox ids became literal ids (`shippingAddressRequired1`, `listOption1`, `bannerOption1`), so labels and markup are unchanged.
- Password inputs carry a static `value=""`. Thymeleaf wrote it; Tessera never writes a bound value on passwords.
- `orders.html` / `products.html` check `x == null or x.isEmpty()`. `Model.addAttribute(emptyList)` does not add anything, and Thymeleaf's `#lists.isEmpty(null)` used to hide that.

### Raw HTML from the database (`th:utext`)
`product.description` (search results, item page) and `account.bannerName` (footer banner) were printed raw with `th:utext`. They are now rendered as an `<img t:src>` built from the parsed `src`, followed by the remaining text, escaped. With the shipped data the page is identical, because the browser turns `<image>` into `<img>`. A value that doesn't match the `<image src="...">text` shape now shows as escaped text instead of being injected as markup. That change is intended: no `SafeHtml.unchecked` was used.

### Tests
- New `ui/ViewRenderingTests` renders through the real view resolvers and checks three things: search keywords are escaped (`<script>` comes out as `&lt;script&gt;`), product descriptions render image and text, and the cart's POST form gets the CSRF input. Existing tests are untouched.

### Migration artifacts
- `pages.txt`: 84 requests covering every view and state. That includes anonymous and logged-in browsing, an empty, full and invalid cart, registration (empty, invalid, valid), login error, account update (invalid, valid), the full checkout (basic form invalid/valid, shipping form invalid/valid, confirm, a DB error 500, success), order list (empty and full) and detail, 400/404/500 error pages, direct `/error`, the Whitelabel 403, and users with and without MyList/MyBanner.
- To reproduce: start both apps with `--spring.datasource.url=jdbc:hsqldb:mem:jpetstore`, then run `java -jar .tessera/tessera-migrate.jar compare http://localhost:8081 pages.txt baseline/ --ignore "<div id='created'>[^<]*</div>" --ignore "[0-9]{4}/[0-9]{2}/[0-9]{2} [0-9]{2}:[0-9]{2}:[0-9]{2}"`. The two masks cover the Whitelabel page's timestamp and the order timestamp (the time of day differs between runs). `baseline/` and `.tessera/` are git-ignored.

## Not converted
Nothing. `static/index.html` and `static/help.html` are static resources, not views, and were left alone. The old index page still says "Thymeleaf" in its welcome text; changing it would break parity for `GET /`.

## Pre-existing build problems (not caused by the migration, not changed)
- **OWASP `dependency-check-maven` 3.2.1** (bound to `verify`) downloads the NVD 2.0 XML feeds. NIST has retired them, so the download returns non-200, the plugin reports "Unable to download the NVD CVE data" and fails the build. The original, unmodified application fails in exactly the same place. All tests run and pass before it. I did not change or disable the security scanner, because that would weaken a security check. Fixing it means upgrading the plugin to a version that uses the NVD API (with an API key).
- **JDK 16+**: Lombok 1.16.22 cannot run on JDK 21 (`module jdk.compiler does not "opens com.sun.tools.javac.processing"`), so the app does not compile on the default JDK 21, before or after the migration. The project targets Java 8 (`java.version` 1.8), and on JDK 8 it builds and passes its tests.

## Where Tessera or its documentation fell short
1. **Code-generation bug on JDK 8: type-use annotations in a cast.** For an indexed form path (`*{lines[i].quantity}`), the generated code casts to the property type using `TypeMirror.toString()`. On javac 8 that string includes the Bean Validation 2.0 type-use annotations on the field: `((@javax.validation.constraints.NotNull,@javax.validation.constraints.Min(0L) :: java.lang.Integer)) ...`. The result is uncompilable Java in `target/generated-sources` ("illegal start of expression"), reported against the generated file rather than the template. Workaround: a hand-written getter whose return type carries no annotations.
2. **Error pages under Boot are not found.** The starter registers no `TemplateAvailabilityProvider`, so Boot's `DefaultErrorViewResolver` never sees `templates/error/404.html` (or `4xx`/`5xx`) and falls back to the Whitelabel page. The guide only mentions `templates/error.html`. Fix: a ten-line provider over `TemplateRegistry`, which the starter should ship.
3. **No `th:include` equivalent, and it isn't documented.** The guide only says "use `t:insert`". It doesn't say how to insert a fragment's *children*, or whether a fragment can carry its own `t:object` for a form section. `t:fragment` + `t:object` + `t:remove="tag"` on the fragment root works, but I had to find that out by trying it.
4. **Thymeleaf form-markup details aren't covered.** Thymeleaf numbers checkbox ids (`listOption1`) and writes `value=""` on password fields. Tessera does neither, and `#ids` has no replacement. The guide doesn't list these as expected differences, and `compare` flags them.
5. **`numbers.formatDecimal` has no grouping separator**, so `#numbers.formatDecimal(x, 1, 'COMMA', 2, 'POINT')` needs a custom function. The guide does mention this.
6. **No safe way to keep stored HTML.** `th:utext` of data from the database has no sanctioned path short of `SafeHtml.unchecked` (forbidden here). There is no sanitizer-backed `SafeHtml` factory, so I had to parse the data into structured values.
7. **The `tessera-migrate` report has false positives.** Bare link parameters (`@{/cart(add, itemId=...)}`, `@{/accounts/create(form)}`) were stubbed as `Object add` / `Object form` template parameters.
8. **Spring's empty-collection quirk.** `Model.addAttribute(emptyList)` adds nothing, so the parameter is `null` and `list.isEmpty()` throws an NPE at render time (a 500). The guide's "missing model attribute is null" rule covers this in principle, but this common case deserves its own note.
9. **The guide doesn't warn about Maven-plugin interaction.** A `license-maven-plugin`-style `format` goal rewrote `pages.txt` and the `baseline/` files, which broke `compare`'s request list.
