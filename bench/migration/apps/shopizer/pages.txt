# shopizer 2.17.0: the admin, then the storefront in each of its four templates, then a customer.
# Requests run in order against the default store the app seeds on first start (start.sh), clock
# at 2025-06-15 10:00 UTC. The seed has no catalogue, so the admin forms build one first; each
# form is posted invalid first (a non-number in a number field, a duplicate code, a missing
# field) where the app validates it. Ids in the URLs are the ones those posts create.
#
# Not here: the order pages (admin order edit, invoice, transactions; the storefront checkout,
# confirmation and order detail), because an order needs a cart, which only the storefront's JSON
# API fills; the file uploads (product images, digital products, store logo, content images),
# which are multipart; the storefront's missing-product page, which prints a stack trace; and
# the admin's JSON endpoints (the lists are filled by script from them). The admin session ends
# when the customer signs up, so the customer pages come last.
