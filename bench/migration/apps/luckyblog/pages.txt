# luckyblog (Apache Velocity): every page template (VM_global_library.vm's macros and the module/
# header, admin-header and footer includes through them), the admin pages behind the login, each
# admin form's failing and succeeding post, and the error pages. Requests run in order against a
# fresh in-memory H2 seeded from seed.sql (posts 1-26, projects 1-11, admin jcala/admin), with the
# clock starting at 2025-06-15 (start.sh), so the post added below is dated Jun 15, 2025. It is
# post 28: the failed insert before it uses up id 27.
#
# The app has no server-side validation and no CSRF token. Its forms post through JavaScript (the
# login and password forms send MD5 hashes); the requests below send what that JavaScript sends.
# A form's failing state is what the app shows when the database rejects the change (a missing
# NOT NULL column): admin/result.vm with "Operation failed!", or a redirect with result=fail/1.
#
# Not covered: picture upload (multipart; /admin/file/uplPic.action returns JSON), /pic/** (files
# under /data) and the admin monitor's memory figures (ignored in app.json: free memory changes).
# A successful login redirects to /admin, which the app does not map: a 404, recorded as such.
